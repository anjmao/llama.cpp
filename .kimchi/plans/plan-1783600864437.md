## Decision Log
- **Correlation key:** `completion_id` (`oaicompat_cmpl_id`) because it is already generated per request and streamed back to the UI.
- **Aggregation location:** server-side, storing per-completion counts/backends instead of raw samples to keep memory bounded.
- **Endpoint path:** `/v1/moe/routed-experts/completion` to live alongside the existing SSE endpoint.
- **Persistence:** store the server response JSON blob on `DatabaseMessage` so the heatmap survives reloads.

## Risks
- **Concurrent/batched slots:** tokens from multiple slots can be decoded in one batch. Mitigation: capture `id_slot` per token and look up each slot’s `oaicompat_cmpl_id` before decode.
- **Speculative decoding:** draft tokens may generate samples not in the final response. Mitigation: samples are attributed to the completion that triggered the decode, which is acceptable for a diagnostic heatmap.
- **Memory growth:** per-completion aggregations are capped at `max_cmpl_completions = 1000`; oldest dropped on overflow.
